No implemented runtime truth yet.

Verified project baseline:
- AgentTeam is a Rust-first framework project.
- Initial work must create architecture/module docs and file structure before code.
- Runtime must avoid fallback, duplicate owner logic, and cross-module internal state access.
- `TANote.md` is now specified as an agent-readable forum-style collaboration projection: agents post through CLI/daemon, TANote Board owns format/order/thread projection, and task/message/event truth remains in daemon-owned modules.
- Local AgentTeam skill must include YAML frontmatter; otherwise Codex skips it and Kevin/worker CLI guidance is unavailable.
- MVP debug requires Resource Lifecycle evidence: every long-lived resource has owner/scope/lease/release policy, orphan/leak/growth detection, event persistence, debug snapshot, and exact-handle cleanup.
- Debug capture is durable in v1: debug bundles/evidence/snapshots must be persisted before CLI/UI output claims them.
- Daemon/session close must run scoped resource cleanup and tracked temporary file cleanup; v1 avoids aggressive memory hard caps but forbids unbounded growth without release/drain/cleanup visibility.
- Function map is a hard implementation gate: no feature work without map owner/contracts/paths/gates and verification mapping.
- Rust source size policy: hand-written Rust leaf files have a 500-line hard limit; shared blocks/contracts are not exempt and should be split by owner/domain/node.
- Local skill split: `agentteam` is the runtime/CLI collaboration surface; `agentteam-dev` is the repository module-development cycle skill.
- Daemon domain design: zterm may expose multiple daemons, so AgentTeam agent names are domain-local. Cross-daemon addressing uses Daemon Domain Registry and canonical `agent@domain`; Communication Center must consume route plans instead of parsing domain strings itself.
- tmux loopback MVP truth: `agentteam tmux loopback --runtime-home <path> --session-count <n> --json` is the first verified multi-session adapter smoke. It creates managed `TA-...` sessions through `agentteam-tmux`, uses `sh -lc` to keep the session process alive, captures pane output with `tmux capture-pane -pJ` so wrapped markers stay matchable, and cleans exact session handles only. Verified with 2 sessions and no residual `TA-agentteam-tmux-smoke-loopback*` sessions.
- Communication Center truth: comm now owns typed message, broadcast, ready report, task-board query, and task claim routing envelopes. `agentteam-comm` validates and accepts those requests without owning task state, and `agentteam-contracts::comm` carries the adjacent-node contracts for the same routes. Verified by `cargo xtask verify` after splitting comm tests out of `comm/mod.rs` to keep every hand-written Rust leaf file under 500 lines.
- Phase 0/Phase 1 MVP scaffold truth: `cargo xtask red-tests` now performs static scans for red-test plan coverage, broad kill patterns, agent-facing transport internal leaks, TOML parsing outside Config Center, state-file writes outside Persistence, domain parsing outside Daemon Domain Registry, non-adjacent `From/TryFrom` pipeline conversions, and contract feature_id coverage.
- Function map gate truth: every Rust function or method under `crates/` and `xtask/src/` must have a matching function-level registry entry in `docs/architecture/function-map.md`; otherwise `cargo xtask verify-function-map` fails. The canonical `cargo xtask verify` runs function-map verification before compile/test gates.
- Phase 1 contracts truth: `agentteam-contracts` now owns typed MVP nodes for config, domain, persistence, error, debug, and resource chains with adjacent-node builders and 13 unit tests. This is contract scaffold only, not business runtime behavior.
- Phase 2 Config Center truth: `agentteam-config` is the only crate with TOML parsing, using `toml::from_str` inside `parse_config_toml`. It loads explicit config paths, parses `docs/config/config.toml.example`, validates project/team/domain/member rules, normalizes runtime config, and creates redacted config snapshots. Verified by `cargo xtask verify` with 7 Config Center unit tests.
- Phase 3 Daemon Domain Registry truth: `agentteam-runtime::domain` is the only owner that parses domain-qualified targets. It registers one local domain plus remote domains, enforces id/alias uniqueness, resolves bare targets to local only, resolves `agent@domain`, `role:<role>@domain`, `team:<team>@domain`, and `all@domain`, returns local/remote route plans, and rejects unknown remote domains without fallback. Verified by `cargo xtask verify` with 7 runtime domain tests.
- Phase 4 Persistence Event Log truth: `agentteam-persist` is the only state-file writer owner for MVP event JSONL. It appends typed event records, returns `PersistResp03AppendReceipt`, replays from zero or a sequence, materializes latest sequence into `PersistResp05MaterializedState`, and fails explicitly on corrupt JSONL, sequence mismatch, or empty event drafts. Verified by `cargo xtask verify` with 7 Persistence unit tests.
- Phase 5 Error Center truth: `agentteam-error` exposes `handle_framework_fault` as the public framework-fault entrypoint. It classifies fault facts, generates `<module>.<class>.<specific>.<time>.<seq>` codes, creates independent `evidence_id`, persists a framework error event through `agentteam-persist`, then returns `TeamErr04Projection`. Normal `task.agent_task_error` is rejected as Task Engine state, and persistence failure does not project success. Verified by `cargo xtask verify` with 6 Error Center unit tests.
- Phase 6 Debug/Resource truth: `agentteam-resource` owns MVP resource leases and persists acquire/release/leak events through Persistence; `agentteam-debug` owns debug bundle capture and must acquire/release a `debug_bundle` lease, include a public Resource snapshot, persist the debug bundle event, and return `DebugResp03Bundle` with persistence receipt and resource snapshot id. Verified by `cargo xtask verify` with 5 Resource tests and 3 Debug tests.

Current CLI output is parse-only and explicitly includes `local_parse_only: true`; it must not claim Config/Domain/Debug business execution until owner APIs are wired behind the intent.
- Local CLI owner execution truth: `agentteam-cli` now parses through Gateway, executes `TeamReq03ValidatedIntent` through `agentteam-runtime::local::execute_local_intent`, and renders through Output Gateway. `config check` calls Config Center, `domain resolve` builds Domain Registry from Config Center validated user config and calls Domain Registry resolution, and `debug snapshot` persists resource/debug events under the requested runtime home. Verified by `cargo xtask verify` plus CLI smoke.
